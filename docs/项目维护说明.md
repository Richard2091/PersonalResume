# 项目维护说明

本文档用于约束 `README.md`、`docs/guide/MD简历渲染手册.md`、示例简历和展示图片的维护方式，避免文档内容、构建产物和仓库首页展示不同步。

## 维护原则

- `README.md` 面向首次进入仓库的使用者，只保留项目定位、快速开始、目录结构、开源边界和关键入口。
- `docs/guide/MD简历渲染手册.md` 面向需要理解 Markdown 简历体系的维护者，说明编写规范、渲染思路和发布方案。
- `versions/sample-java-backend/resume.md` 是公开示例源文件，示例内容变更后必须同步检查 HTML、PDF 和 README 展示图。
- `assets/demo/social-preview.png` 和 `assets/demo/resume-preview.png` 是 README 中直接展示的图片，任何影响首页视觉预览的变更都必须重新生成或重新截图。
- 公开仓库不得提交真实个人隐私、投递材料、面试题库或内部项目证据。

## README 维护

修改 `README.md` 时优先保持短链路阅读：

- 项目定位变化时，同步更新标题下方简介、功能亮点和目录结构。
- 构建命令变化时，同步更新快速开始、配置说明和 `package.json` 中的脚本。
- 目录或文件职责变化时，同步更新目录结构，不保留已经不存在的路径。
- README 图片路径必须使用仓库内相对路径，当前固定为 `assets/demo/social-preview.png` 和 `assets/demo/resume-preview.png`。
- 修改 README 后至少检查一次 Markdown 预览，确认图片、表格、代码块和相对链接可以正常渲染。

## 渲染手册维护

修改 `docs/guide/MD简历渲染手册.md` 时要保证手册描述与项目实际能力一致：

- 新增或调整 Markdown 结构规则时，同步检查 `scripts/build-resume.mjs` 对标题、段落、项目元信息和联系信息的解析逻辑。
- 新增或调整样式规则时，同步检查 `styles/resume-single-column.css` 与生成后的版本样式 `versions/<版本名>/resume.css`。
- 新增或调整发布方案时，区分已经在本仓库落地的能力和仅作为建议的能力，不把未实现功能写成现有功能。
- 示例片段应使用虚拟信息，不写真实手机号、邮箱、内部项目名称或不可公开链接。

## 示例和产物维护

修改以下内容后，必须重新构建默认示例版本：

- `versions/sample-java-backend/resume.md`
- `styles/resume-single-column.css`
- `scripts/build-resume.mjs`
- `resume.config.json`
- `assets/icons/` 或 `assets/fonts/` 下会影响渲染的资源

执行命令：

```bash
npm run build -- --version sample-java-backend
npm run check
```

构建完成后检查这些产物：

- `versions/sample-java-backend/index.html`
- `versions/sample-java-backend/resume.css`
- `versions/sample-java-backend/resume.pdf`
- `export/sample-java-backend.html`

如果是第一次拉取项目，先执行：

```bash
npm install
```

如果本机没有自动识别到 Chromium 内核浏览器，按 README 中说明设置 `RESUME_CHROME_PATH` 后再构建。

## README 展示图片维护

每次修改默认示例、公共样式、渲染脚本、首页视觉描述或仓库封面信息后，都要重新生成 README 中的展示图片：

- `assets/demo/resume-preview.png`：由 `versions/sample-java-backend/resume.pdf` 的第一页按 A4 144 DPI 渲染生成。
- `assets/demo/social-preview.png`：由仓库封面文案和最新 `assets/demo/resume-preview.png` 合成，文案和视觉风格应与当前 README 保持一致。

当前图片规格：

| 图片 | 建议尺寸 | 用途 |
| --- | --- | --- |
| `assets/demo/resume-preview.png` | 1190 × 1684 | README 示例简历预览 |
| `assets/demo/social-preview.png` | 1280 × 640 | README 仓库封面 |

更新顺序：

1. 运行 `npm run build -- --version sample-java-backend` 生成最新 HTML 和 PDF。
2. 打开 `versions/sample-java-backend/index.html` 或 PDF，确认首屏、分页、水印和中文字体显示正常。
3. 将 `versions/sample-java-backend/resume.pdf` 第 1 页按 A4 144 DPI 渲染并覆盖 `assets/demo/resume-preview.png`。
4. 使用最新 `assets/demo/resume-preview.png` 重新合成并覆盖 `assets/demo/social-preview.png`。
5. 在 README 预览中确认两张图片都能加载，且没有使用过期样例内容。
6. 运行 `npm run check` 确认构建产物仍然有效。

当前仓库没有单独的 PNG 自动生成脚本，因此不要只修改 `resume.md` 或 CSS 后提交代码而保留旧图片。若后续新增图片生成脚本，需要同步更新本文档和 `package.json` 脚本说明。

## 提交前检查

提交前按变更范围执行检查：

| 变更范围 | 必做检查 |
| --- | --- |
| 仅修改普通文档 | 检查 Markdown 预览、相对链接和公开信息边界 |
| 修改 README | 检查 README 预览、图片路径和目录结构 |
| 修改示例内容或样式 | 执行 `npm run build -- --version sample-java-backend` 和 `npm run check`，并更新 README 展示图片 |
| 修改构建脚本或配置 | 执行默认示例构建、`npm run check`，检查 HTML、PDF、导出入口和 README 说明 |
| 新增简历版本 | 更新 `resume.config.json` 和 `versions/README.md`，按版本执行构建和检查 |

确认没有提交以下内容：

- 真实个人联系方式、身份证明、投递记录或内部项目证据。
- 本地浏览器路径、临时调试日志或个人环境配置。
- 与当前样例不一致的过期 README 图片。
